# Privacy

NutriMind AI is a personal-nutrition assistant. Using it means telling it things
about your health. This explains what happens to that information.

Plain language on purpose. It is a description of what the software actually
does — every claim here corresponds to code in this repository, and the sections
below name it.

## What is collected

Only what you enter. There is no tracking, no analytics, no advertising, and no
third-party scripts that report on you.

| | |
|---|---|
| **Account** | Email address, display name, hashed password |
| **Profile** | Age, gender, height, weight, activity level, dietary preference, goal, medical conditions, allergies, country, timezone |
| **Tracking** | BMI history, water intake, meals you log |
| **Chat** | Your messages and the assistant's replies |
| **Documents** | PDFs you upload, and the text extracted from them |

Your **medical conditions and weight history are health information**. They are
treated as the most sensitive data here.

## What is *not* collected

- No analytics, no cookies except the two that keep you signed in, no tracking
  pixels, no third-party embeds that profile you.
- Your password is never stored — only a scrypt hash, which cannot be reversed.
- **Your chat messages are not written to the logs.** Routing and retrieval log a
  length and a random per-run fingerprint instead of your text, so operational
  debugging never involves reading what you asked.

## Where it goes

**Your data stays on the server running this instance.** SQLite (or PostgreSQL)
for records, ChromaDB for document vectors, and the filesystem for uploaded PDFs.

One exception, and it is opt-in. If the operator has configured IBM watsonx.ai,
your message and any retrieved passages are sent to IBM to generate a reply, and
handled under IBM's terms. Without those credentials the application runs in demo
mode and **nothing leaves the server at all**. The interface always shows which
mode is active.

## Who can see it

Only you. Every record is scoped to your account, in the database and in the
vector store, and this is enforced in code rather than by convention —
`tests/integration/test_tenancy.py` exists specifically to prove one account
cannot reach another's data.

The operator of an instance has administrative access to the server, as with any
self-hosted application.

## How long it is kept

Until you delete it. There is no automatic expiry — your own history is the point
of a tracking application.

- **Delete individual documents** from the Knowledge page at any time.
- **Delete your entire account** from the Profile page. This removes your rows,
  your uploaded files and your document vectors, then signs you out. It is
  immediate and cannot be undone.
- **Export everything** as JSON before you go, from the same page.

Backups may hold your data for up to 14 days after deletion, because backups are
snapshots and a snapshot cannot selectively forget. They are retained by the
operator and rotate out.

Application logs, which contain no message content, rotate within a few
megabytes.

## Automated decisions

NutriMind generates nutrition guidance using a language model. It is **not
medical advice**, it does not diagnose, and it should not replace a clinician.

Answers drawn from your uploaded documents are labelled **grounded** and cite the
file and page. Anything else is labelled **general knowledge**. That distinction
is deliberate and enforced: citations are assembled from retrieval metadata, not
generated by the model, so the application cannot invent a source.

## Your choices

| You want to | Do this |
|---|---|
| See everything held about you | Profile → Export data |
| Correct something | Edit your profile |
| Delete one document | Knowledge → delete |
| Delete everything | Profile → Delete account |
| Stop data leaving the server | Ask the operator to run in demo mode |
